## tipos de VLANs
- **default VLAN:** todos los puertos en un switch cisco estan en VLAN 1, a menos que se especifique lo contrario. consideraciones de VLAN 1
	- todos los puertos estan asignados a VLAN 1 por default
	- la VLAN nativa es VLAN 1 por default
	- la administracion VLAN es VLAN 1 por default
	- VLAN 1 no se puede reescribir o eliminar
- **data VLAN**: estan configuradas para separar el trafico generado por usuarios. una red moderna puede tener varios data vlans - voces y manejo de trafico de red no deben ser permitidos en este tipo
- **native VLAN**: el trafico de una VLAN debe ser taggeado con su **VLAN ID** cuando es enviado a otro switch.
	- se utilizan puertos trunk entre switches para soportar la transmision de trafico con tag
	- # **un puerto trunk 802.1Q** inserta un tag de 4 bytes en el frame ethernet para identificar el VLAN al que el frame pertenece
		- este puerto trunk coloca trafico sin taggear en la VLAN nativa
- **management VLAN:** configurada especificamente para el manejo de red, incluyendo trafico SSH, telnet, HTTPS, HTTP, y SNMP.
	- VLAN 1 es configurada por default como el management VLAN en switches de layer 2
- **voice VLAN:** para soportar VoIP. requiere lo siguiente
	- suficiente bandwidth para asegurar calidad de voz
	- prioridad de transmision por sobre otros tipos en el trafico de red
	- habilidad para ser routeado en areas congestionadas en la red
	- un delay menor a 150ms a traves de la red

## VLAN trunks
permiten que todo el trafico VLAN se propage entre switches. permite que dispositivos conectados en diferentes switches pero en la misma VLAN comunicarse sin tener que pasar por un router.

cisco soporta IEEE 802.1Q para coordinar trunks en Fast Ethernet, Gigabit Ethernet y 10-Gigabit Ethernet interfaces

**los trunk ports** no pertenecen a ninguna VLAN especifica

### redes sin VLANs
los frames broadcast alcanzarian a toda la subnet

## tag de identificacion VLAN
usando el header IEEE 802.1Q que incluye un tag de 4 bytes
cuando un switch recibe un frame en un puerto configurado en access mode y asignado a una VLAN, el switch inserta un tag VLAN en el frame header, recalcula el FCS, y envia el frame taggeado en un trunk port
%%> como es un puerto configurado en access mode? que otros modos hay?%%
detalles del tag field:
- type: un valor de 2 bytes llamado **tag protocol ID (TPID)**. para ethernet se setea al numero hexadecimal 0x8100
- user priority: un valor de 3 bits que soporta implementacion de nivel o de servicio
- canonical format identifier (CFI): un identificador de 1 bit que permite a los frames token ring ser llevados a traves de links ethernet
- VLAN ID (VID): numero de identificacion de 12 bits que soporta hasta 4096 VLAN ID's

## native VLAN y tagging 802.1Q
el standard IEEE 802.1Q especifica una VLAN nativa para links trunk, que por default usa VLAN 1
**cuando llega un frame sin tag al trunk port, se lo asigna al native VLAN**
- los management frames que se envian entre switches son un ejemplo de trafico que generalmente viaja sin tagearse

### frames taggeados en la native VLAN
el control de trafico enviado al native VLAN no debe ser tageado. si un puerto trunk 802.1Q recibe un tag frame con el VLAN ID que es el mismo que el native VLAN, dropea el frame.
- es ideal configurear un switch port para que no envien frames taggeados en el native VLAN

### frames sin taggear en la native VLAN
cuando un trunk port en un switch cisco recibe frames sin taggear (que es inusual en una red bien disenada), los reenvia a la native VLAN.
si no hay dispositivos asociados al native VLAN y no hay otros trunk ports, entonces se dropea el frame

cuando se configura un trunk port 802.1Q, el puerto default para VLAN ID (PVID) es asignado al valor de VLAN ID nativo. todo el trafico sin tagear entrando o saliendo del puerto 802.1Q es reenviado en base al valor PVID

PC envia trafico sin taggear, entonces los switchs lo asocian al native VLAN configurado en los trunk ports, y lo reenvian acordemente.

## voice VLAN tagging
un VLAN separado para voz es requerido para soportar VoIP
- permite QoS
- permite aplicar politicas de seguridad al trafico de voz

un telefono IP cisco se conecta directamente a un switch port
un IP host tambien se puede conectar al telefono IP para ganar conectividad de red ademas

el puerto de acceso se puede conectar al telefono cisco IP para usar dos VLANs separadas
- una para el trafico de voz
- el otro para el trafico host
el link que conectaria el switch y el telefono IP simula un link trunk para manejar trafico de voz VLAN y trafico de datos VLAN

el cisco IP phone tiene un switch de 3 puerto 10/100 integrado, los puertos proveen conexiones dedicadas para los siguientes dispositivos:
1. conecta al switch o otros dispositivos VoIP 
2. es una interface 10/100 interna que acarrea el trafico del IP phone
3. (access port) conecta a una PC u otro dispositivo

el switch access port envia paquetes CDP instruyendo al telefono IP a enviar trafico de voz en una de 3 maneras. el metodo varia basado en el tipo de trafico
- el trafico VLAN de voz debe ser taggeado con un valor de prioridad de CoS de capa 2 adecuado

rangos normales de VLANs:
- tienen un VLAN ID entre 1 y 1005
- IDs 1002 hasta 1005 son reservadas para tecnologias legacy de red
- IDs 1 y de 1002 a 1005 son creadas automaticamente y no pueden ser removidas
- las configuraciones son guardadas en la memoria flash del switch en una bd del VLAN llamada **vlan.dat**
- cuando esta configurada, el VLAN trunking protocol (VTP), ayuda a sincronizar la base de datos del VLAN entre switches

rangos extendidos de VLAN:
- usadas por proveedores de servicio para brindar servicio a multiples clientes y por empresas globales grandes que necesiten VLAN IDs de rango extendido
- se identifican por un VLAN ID de entre 1006 y 4094
- las configuraciones son guardadas, por default, en la running config
- soportan menos features VLAN que las VLANs de rangos normales
- requiere VTP modo transparente para soportar extended range VLANs

# VLAN trunks
es un link de layer 2 entre dos switches que acarrea el trafico para todas las VLANs
![[Pasted image 20260908121224.png]]
ejemplo
![[Pasted image 20260908121231.png]]
```
S1(config)# interface fastEthernet 0/1  
S1(config-if)# switchport mode trunk  
S1(config-if)# switchport trunk native vlan 99  
S1(config-if)# switchport trunk allowed vlan 10,20,30,99  
S1(config-if)# end
```

el switch cisco catalyst 2960 automaticamente usa encapsulacion 802.1Q en links trunk

para verificar la configuracion del trunk:
```
show interfaces interface-ID switchport
```
#### resetear el trunk al estado default
no switchport trunk allowed vlan
no switchport trunk native vlan

# dynamic trunking protocol DTP
algunos switches cisco tienen un protocolo cerrado que les permite automaticamente negociar trunking con un dispositivo vecino
puede incrementar la velocidad en el proceso de configuracion para un administrador de red. 

un puerto se puede setear a trunking, no trunking o a negociar el trunking con el dispositivo vecino

la negociacion del trunking la maneja DTP

Nota: algunos dispositivos de interworking pueden reenviar frames DTP de forma incorrecta, que puede causar errores de configuracion. **para evitar esto, apagar DTP en interfaces de switches que esten conectadas a dispositivos que no soporten DTP**

en cisco catalyst 2960 y 3650 la configuracion default es dynamic auto

##### habilitar DTP
```
S1(config-if)# switchport mode trunk  
S1(config-if)# switchport nonegotiate
```
para re-activarlo usar:
```
S1(config-if)# switchport mode dynamic auto
```

si los puetos que conectan dos switches estan configurados para ignorar todos los anuncios DTP con los comandos **switchport nonegotiate**, permaneceran en modo **trunk port**, si los puetos de conexion estan configurados en dynamic auto, no negociaran un trunk y permaneceran en access mode state, creando un trunk port inactivo

#### modos de interfaces negociados
el comando `switchport mode` tiene opciones adicionales para negociar el modo de interfaz.

Switch(config)# switchport mode { access | dynamic { auto | desirable } | trunk }

opciones:

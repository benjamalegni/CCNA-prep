# Introduction
Network protocols and reference models are foundational to ensuring that devices can communicate regardless of hardware vendor or underlying technology. **Protocols** are agreed-upon rule sets governing communication, while **reference models** provide a layered framework to understand how these rules operate across network functions.

The overarching goal is interoperability, enabling a source host to efficiently deliver messages to a destination host across shared media.

# Communication Fundamentals
Effective communication requires three primary components:
- **Message Source** (Sender)
- **Message Destination** (Receiver)
- **Channel** (Transmission Medium)

Communication is governed by protocols defining message format, timing, and transmission methods.

**Message Encoding**: Converting information into an acceptable physical format for transmission (electrical pulses, light waves, RF signals). The inverse process is **decoding**.

**Formatting and Encapsulation**: Structuring data according to media requirements (analogous to placing a letter into an addressed envelope).

# Protocol Requirements
- **Message Size**: Regulates the maximum data payload transmitted at once. Large data streams are segmented into smaller blocks.
- **Message Timing**:
  - **Flow Control**: Managing transmission rates to prevent overwhelming receivers.
  - **Response Timeout**: The duration a host waits for an acknowledgment before assuming packet loss.
  - **Access Method**: Determines when a station may transmit on a shared medium to prevent or handle collisions.
- **Delivery Options**:
  - **Unicast**: Delivery to a single, specific end device.
  - **Multicast**: Delivery to a designated group of interested devices.
  - **Broadcast**: Delivery to all devices on the local broadcast domain.

# Protocol Suites
A **protocol suite** is a set of interrelated protocols working together. They operate as a layered stack, where lower layers manage network transmission and upper layers handle application data.

The predominant protocol suite is **TCP/IP**, an open standard maintained by the **IETF**. It superseded proprietary stacks such as AppleTalk and Novell NetWare, guaranteeing multivendor hardware and software interoperability.

# Standards Organizations
Open standards foster innovation and competition, developed by vendor-neutral international organizations:
- **ISOC** (Internet Society), **IAB** (Internet Architecture Board), and **IETF** (Internet Engineering Task Force, which publishes RFCs).
- **ICANN** and **IANA**: Coordinate IP address space allocation and DNS root zones.
- **IEEE**: Defines physical and data link standards, including IEEE 802.3 (Ethernet) and IEEE 802.11 (WLAN/Wi-Fi).
- **TIA/EIA**: Develops cabling and wiring termination standards.

# Reference Models
Layered models modularize network functions, fostering compatibility and isolating layer changes.

#### TCP/IP Suite Protocols by Layer

***Application Layer***
Provides services directly to end-user applications:
- **DNS (Domain Name System)**: Resolves human-readable domain names (e.g., cisco.com) to numeric IP addresses.
- **DHCP (v4 and v6)**: Dynamically leases IP configuration to client hosts.
- **SLAAC**: Stateless IPv6 address autoconfiguration using router advertisements.
- **SMTP**: Email transmission between mail transfer agents (MTAs).
- **POP3 / IMAP**: Protocols used by email clients to retrieve messages from a mail server.
- **FTP**: Reliable, connection-oriented client-server file transfers.
- **TFTP**: Lightweight, connectionless UDP-based file transfer.
- **SFTP**: Secure, SSH-encrypted file transfer.
- **HTTP / HTTPS**: Hypertext Transfer Protocol (cleartext / TLS-encrypted) powering the World Wide Web.
- **REST**: Architectural web service interface utilizing HTTP methods.

***Transport Layer***
Manages end-to-end process-to-process communication between hosts:
- **TCP (Transmission Control Protocol)**: Connection-oriented, reliable, sequenced, stateful byte-stream delivery with flow control and windowing.
- **UDP (User Datagram Protocol)**: Connectionless, lightweight, low-overhead datagram delivery without acknowledgments ("best-effort").

***Internet Layer***
Responsible for logical addressing, path determination, and packet routing:
- **IPv4**: 32-bit logical addressing scheme.
- **IPv6**: 128-bit hierarchical addressing scheme.
- **NAT (Network Address Translation)**: Translates private RFC 1918 addresses into globally routable public IPs.
- **ICMP (v4 and v6)**: Control messaging and error reporting.
- **OSPF**: Open-standard link-state Interior Gateway Protocol (IGP).
- **EIGRP**: Cisco advanced distance-vector routing protocol.
- **BGP**: Exterior Gateway Protocol (EGP) routing the global Internet backbone.

***Network Access Layer***
Manages physical network hardware, signaling, and data link frame exchange:
- **ARP (Address Resolution Protocol)**: Dynamically resolves a known IPv4 address into a Layer 2 MAC address.
- **Ethernet (IEEE 802.3)**: Defines wired LAN framing and signaling.
- **WLAN (IEEE 802.11)**: Defines wireless radio transmission framing.

# Data Encapsulation
**Encapsulation** adds protocol control headers (and trailers) as data moves down the stack from application to physical medium:
- **Data**: Application Layer
- **Segment / Datagram**: Transport Layer (adds source and destination port numbers)
- **Packet**: Network Layer (adds source and destination IP addresses)
- **Frame**: Data Link Layer (adds source and destination MAC addresses and Frame Check Sequence)
- **Bits**: Physical Layer (encoded signal transmission)

# Data Access and Addressing
- **IP Address (Layer 3 Logical Address)**: Identifies the original source and final destination host across routed internetworks.
- **MAC Address (Layer 2 Physical Address)**: Identifies the physical interface on the immediate local segment, rewritten on each router hop.

### Communication on the Same Local Subnet
When the source and destination reside within the same subnet, frames are delivered directly:
- **Source IP**: Local Host IP
- **Destination IP**: Local Target IP
- **Source MAC**: Local Host NIC MAC
- **Destination MAC**: Local Target NIC MAC (resolved via [[resources/ARP|ARP]])

### Communication on a Remote Network
When the destination host is outside the local network:
- **Source IP**: Host IP (e.g., 192.168.1.110)
- **Destination IP**: Remote Server IP (e.g., 172.16.1.99)
- **Source MAC**: Host NIC MAC
- **Destination MAC**: **Default Gateway (Router) Interface MAC**

The router strips the Layer 2 Ethernet frame, examines the destination Layer 3 IP address, performs a route table lookup, and encapsulates the packet into a new Layer 2 frame with the next-hop MAC address.

#### Lab Insights
When pinging a local device, the destination MAC address belongs directly to the target device (obtained via [[resources/ARP|ARP]]).
When pinging a URL/hostname, DNS resolution occurs first to obtain the destination IP address, and the frame is addressed to the default gateway's MAC address.

### Switch Virtual Interface (SVI)
```text
interface vlan 1
 ip address 192.168.1.1 255.255.255.0
 no shutdown
```
- A **logical (virtual) interface**, not tied to a single physical port.
- Provides an **IP address** on the switch.
- Used for **in-band remote management** (SSH, Telnet, SNMP, HTTPS).

![[Pasted image 20260125185216.png]]
When a Layer 2 switch is positioned between two communicating hosts, the frame's destination MAC is either the final host or the router gateway—**never the Layer 2 switch's MAC address**.

# CCNA Review Questions & Concepts
- **Application Layer Protocols in TCP/IP**: DNS, DHCP, FTP, HTTP, SMTP.
- **SSH vs Telnet**: SSH encrypts all communications (credentials and session data), whereas Telnet transmits all data in cleartext.
- **Media Selection Criteria**: Maximum supported distance and the physical operating environment (EMI, temperature, moisture).
- **Remote Management of Layer 2 Switch**: Configured on a Switch Virtual Interface (SVI).
- **Verify Interface Status**: `show ip interface brief`
- **service password-encryption**: Obfuscates passwords in the running configuration file.
- **Layer Adding Logical Address**: Network Layer (Layer 3).
- **Private Collection of LANs/WANs**: Intranet.
- **Layer Adding Port Numbers**: Transport Layer (Layer 4).

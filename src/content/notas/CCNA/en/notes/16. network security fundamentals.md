# Security Risks and Vulnerabilities
A **threat actor** is an individual or group that gains unauthorized access to systems or data by exploiting software bugs, hardware weaknesses, or compromised user credentials.

### Primary Threat Categories:
- **Information Theft**: Accessing a host or network to exfiltrate confidential data.
- **Data Loss and Manipulation**: Breaking into systems to alter or destroy records (e.g., reformatting drives, forging transaction logs).
- **Service Disruption**: Denying legitimate users access to network resources or services (e.g., DoS attacks).

## Physical Security Threats
Compromising physical access to equipment bypasses most logical controls:
- **Hardware Threats**: Physical damage to routers, switches, cabling plants, server chassis.
- **Environmental Threats**: Temperature and humidity extremes.
- **Electrical Threats**: Voltage spikes, brownouts, power line noise, total power loss.
- **Maintenance Threats**: Poor cabling management, ESD damage, lack of critical spare parts, mislabeled ports.

# Network Attacks
### Types of Malware
- **Viruses**: Malicious code attached to an executable file or document. Requires host software execution and human interaction to propagate.
- **Worms**: Standalone programs that self-replicate across network links without needing a host file or human intervention.
- **Trojan Horses**: Malware disguised as useful or legitimate software. Often creates **backdoors** for remote command execution.

### Categories of Attack:
- **Reconnaissance Attacks**: Mapping network topology, discovering active hosts, open ports, and vulnerable services (`whois`, `nslookup`, `nmap`, ping sweeps).
- **Access Attacks**: Exploiting vulnerabilities to gain unauthorized system access or privilege escalation:
  - *Password attacks*: Brute-force, dictionary attacks, packet sniffing.
  - *Trust exploitation*: Pivoting through a trusted intermediary host.
  - *Port redirection*: Compromised host used as a proxy to attack secondary targets.
    ![[Pasted image 20260723144207.png]]
  - *Man-in-the-Middle (MitM)*: Attacker positions between communicating endpoints to intercept and modify traffic.
    ![[Pasted image 20260723144255.png]]
- **Denial of Service (DoS / DDoS)**: Saturates network bandwidth or device CPU/memory resources:
  - **DoS**: Originates from a single attacking source.
  - **DDoS**: Coordinated attack originating from multiple infected hosts (**zombies**) organized into a **botnet** directed by Command and Control (C2) servers.

# Attack Mitigation & Defense-in-Depth
A layered defense-in-depth model ensures that if one security barrier is breached, secondary controls prevent compromise:
![[Pasted image 20260723145353.png]]

- **VPNs**: Secure encrypted tunnels for site-to-site and remote worker connectivity.
- **Cisco ASA Firewall**: Stateful firewall inspecting packet states.
- **IPS vs. IDS**:
  - **IDS (Intrusion Detection System)**: Operates **out-of-band** (promiscuous mode); monitors traffic copies and generates alerts.
  - **IPS (Intrusion Prevention System)**: Operates **in-line**; actively intercepts traffic in real-time to drop malicious packets and terminate sessions.
- **ESA / WSA**: Dedicated Email and Web Security Appliances filtering spam, phishing, and malware domains.
- **AAA Server (Authentication, Authorization, Accounting)**: Centralized management and identity verification.

### Security Framework Approaches:
- **Layered (Defense-in-Depth)**: Redundant security controls at network, host, and application layers.
- **Structured**: Standardized security policies, compliance frameworks, and procedures.
- **Risk-Based**: Prioritizes defensive investments based on asset valuation and threat likelihood.
- **Attack-Based**: Focuses defenses against specific known exploit vectors and signatures.

# Authentication, Authorization, and Accounting (AAA)
- **Authentication**: *"Who are you?"* (Verifies user identity via credentials, tokens, or certificates).
- **Authorization**: *"What are you allowed to do?"* (Determines accessible commands, privilege levels, and services).
- **Accounting**: *"What did you do?"* (Logs user commands, timestamps, and resource utilization for auditability).

---

# Firewalls
Positioned at network perimeters to permit or deny traffic based on established security policies.

### Firewall Architectures:
- **Packet Filtering (Stateless)**: Evaluates individual packets against ACL rules (source/destination IP, port, protocol) in isolation.
- **Stateful Packet Inspection (SPI)**: Maintains a dynamic state table of active connections. Inbound packets are only permitted if they are legitimate responses to established outbound sessions.
- **Application Filtering**: Inspects application payloads (e.g., HTTP headers, SQL commands).
- **URL Filtering**: Blocks traffic based on URL patterns or domain categories.
- **Demilitarized Zone (DMZ)**: A perimeter subnet hosting public-facing servers (web, mail, DNS) isolated from the internal enterprise network.

# Securing Cisco Devices
```text
Router(config)# service password-encryption
Router(config)# security password min-length 10
Router(config)# login block-for 180 attempts 4 within 120
Router(config)# no ip domain-lookup
```

### Configuring SSH on a Cisco Switch / Router
1. Set the hostname:
   ```text
   S1(config)# hostname S1
   ```
2. Set the domain name:
   ```text
   S1(config)# ip domain-name CCNA.com
   ```
3. Create a local administrator account:
   ```text
   S1(config)# username admin secret ccna
   ```
4. Generate RSA keys (minimum 1024 bits for SSHv2):
   ```text
   S1(config)# crypto key generate rsa
   How many bits in the modulus [512]: 1024
   ```
5. Enforce SSH on VTY lines:
   ```text
   S1(config)# line vty 0 4
   S1(config-line)# login local
   S1(config-line)# transport input ssh
   S1(config-line)# exec-timeout 6 0
   S1(config-line)# exit
   S1(config)# ip ssh version 2
   ```

# Command Summary Table
| Command | Mode | Purpose |
| --- | --- | --- |
| `enable secret <pass>` | Global Config | Encrypts privileged EXEC password with strong hash |
| `service password-encryption` | Global Config | Weakly encrypts all plaintext passwords in configuration |
| `security password min-length 10` | Global Config | Enforces minimum password length |
| `login block-for 180 attempts 4 within 120` | Global Config | Mitigates brute-force attacks by locking login attempts |
| `crypto key generate rsa` | Global Config | Creates asymmetric key pairs required by SSH |
| `transport input ssh` | Line Config (VTY) | Restricts remote management exclusively to encrypted SSH |
| `login local` | Line Config | Configures lines to authenticate against local database |
| `interface range <range> / shutdown` | Interface Config | Disables unused switch ports to prevent unauthorized access |
| `copy running-config startup-config` | Privileged EXEC | Saves running configuration to non-volatile RAM (NVRAM) |

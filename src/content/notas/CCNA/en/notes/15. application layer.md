# Application Layer Overview
The Application Layer represents the interface between the user/software application and the underlying network.
In the **TCP/IP model**, the Application Layer encompasses the functions of the top three layers of the **OSI model**:
- **Application (Layer 7)**: Provides protocols used by software applications to communicate across networks (HTTP, FTP, TFTP, DNS).
  ![[Pasted image 20260720121349.png]]
- **Presentation (Layer 6)**: Formats/structures data, performs compression, and handles encryption and decryption.
- **Session (Layer 5)**: Initiates, maintains, and terminates dialogues between communicating source and destination applications.

# TCP/IP Application Layer Protocols
| Service | Protocol | Transport Protocol & Port | Description |
| --- | --- | --- | --- |
| **Domain Name System** | **DNS** | UDP / TCP 53 | Resolves human-readable domain names into IP addresses. |
| **Host Configuration** | **DHCP** | UDP 67 (Server), 68 (Client) | Dynamically assigns IPv4 addressing and network configuration parameters. |
| **Legacy Host Config** | **BOOTP** | UDP 67, 68 | Legacy diskless workstation bootstrap protocol (superseded by DHCP). |
| **Email Transmission** | **SMTP** | TCP 25 | Sends email from clients to servers and between mail transfer agents. |
| **Email Retrieval** | **POP3** | TCP 110 | Retrieves and downloads emails locally from server; deletes server copy. |
| **Email Management** | **IMAP** | TCP 143 | Synchronizes email mailboxes between clients while keeping messages on server. |
| **File Transfer** | **FTP** | TCP 20 (Data), 21 (Control) | Reliable, connection-oriented client-server file transmission. |
| **Lightweight File Transfer** | **TFTP** | UDP 69 | Best-effort, connectionless file transfer with minimal overhead (no authentication). |
| **Web Browsing** | **HTTP** | TCP 80 / 8080 | Delivers hypertext resources (HTML, images, media) across the web. |
| **Secure Web Browsing** | **HTTPS** | TCP / UDP 443 | Encrypted HTTP communication using TLS/SSL authentication. |

# Client-Server vs. Peer-to-Peer (P2P)
### Client-Server Architecture
In a client-server model, dedicated servers host centralized resources, and clients initiate requests to access those resources. Uploading describes transferring data from client to server, while downloading refers to data traveling from server to client.

### Peer-to-Peer (P2P) Networks and Applications
- In P2P networks, two or more connected endpoints share resources (files, printers) without requiring a central server.
- Each participating host can simultaneously function as both a **client** and a **server** for different simultaneous transactions.
- P2P applications maintain an active background daemon to service inbound peer queries while providing a user interface.

# Web & Email Protocols
### HTTP & HTML
HTTP is a request/response client-server protocol.
1. Browser parses URL: protocol (`http`), server hostname (`www.cisco.com`), resource path (`index.html`).
2. Performs a DNS query to obtain the server's IP address.
3. Establishes a TCP connection on port 80 and submits a **GET** request.
4. Server replies with HTTP response headers and the HTML payload.
5. Browser renders HTML content.

Common HTTP Methods:
- **GET**: Requests data or pages from the web server.
- **POST**: Submits web form data to be processed by the server.
- **PUT**: Uploads or replaces designated files/resources on the server.

### Email Infrastructure (SMTP, POP3, IMAP)
![[Pasted image 20260720130344.png]]

- **SMTP (Simple Mail Transfer Protocol)**:
  - Formats messages requiring a header and body.
  - Clients send outgoing messages to their local mail server over TCP port 25.
  - Servers route and spool messages toward the destination server; if undeliverable after timeout, bounces back to sender.
- **POP3 (Post Office Protocol v3)**:
  - Listens on TCP port 110.
  - Downloads emails to the client device and deletes them from the server.
  - Not recommended when centralized multi-device backup is required.
  ![[Pasted image 20260720132311.png]]
- **IMAP (Internet Message Access Protocol)**:
  - Listens on TCP port 143.
  - Keeps master copies on the server while caching synchronized copies on client devices.
  - Folder structures and deletion states remain synchronized across all client devices.
  ![[Pasted image 20260720132624.png]]

# Addressing & Name Resolution Services
### Domain Name System (DNS)
- Matches human-readable Fully Qualified Domain Names (FQDNs) to numeric IP addresses.
- Queries typically run over **UDP port 53**; zone transfers and oversized replies use **TCP port 53**.
- DNS record types:
  - **A**: IPv4 address record.
  - **AAAA**: IPv6 address record.
  - **NS**: Authoritative Name Server record.
  - **MX**: Mail Exchange record.
  - **CNAME**: Canonical name (alias).

![[Pasted image 20260722111418.png]]

### Dynamic Host Configuration Protocol (DHCP)
- Automatically allocates IPv4 addresses, subnet masks, default gateways, and DNS server addresses from a configured pool.
- Eliminates manual configuration errors and simplifies subnet renumbering.

![[Pasted image 20260722111913.png]]

#### DHCP Four-Step Operation (DORA):
1. **Discover (DHCPDISCOVER)**: Client broadcasts to locate active DHCP servers (`255.255.255.255`).
2. **Offer (DHCPOFFER)**: Server reserves an IP address and sends an offer packet with lease duration and network settings.
   ![[Pasted image 20260722112257.png]]
3. **Request (DHCPREQUEST)**: Client broadcasts an acceptance of the offered lease.
4. **Acknowledgment (DHCPACK)**: Server confirms the lease binding (or returns DHCPNAK if invalid).

# File Sharing Services
### FTP (File Transfer Protocol)
- Requires two separate connections:
  - **Control connection**: TCP port 21 (handles commands and responses).
  - **Data connection**: TCP port 20 (handles actual data transfer).

![[Pasted image 20260722113431.png]]

### SMB (Server Message Block)
- Client-server file, directory, and printer sharing protocol.
- Clients establish long-term authenticated connections to server resources.
- SAMBA is the open-source implementation used by Linux/UNIX systems to interoperate with Windows SMB networks.

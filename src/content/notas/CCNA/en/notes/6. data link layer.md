# Data Link Layer Overview
Prepares network data for physical transmission. Responsible for Network Interface Card (NIC) communications across the physical network media.
- Allows upper protocol layers to access the media without concern for physical wiring details.
- Accepts Layer 3 data packets (IPv4 or IPv6) and encapsulates them into Layer 2 frames.
- Controls how data is placed and received on the media (Media Access Control).
- Exchanges frames between endpoints across local network media.
- De-encapsulates received frames and routes the Layer 3 payload to the proper upper-layer protocol.
- Performs error detection, rejecting corrupted frames using frame check sequences.

The Data Link layer prepends Layer 2 source and destination addresses (such as MAC addresses) and appends a trailer containing error-detection data.

## IEEE 802.2 LAN/MAN Sublayers
The IEEE 802 LAN/MAN standard divides the Data Link Layer into two distinct sublayers:
1. **Logical Link Control (LLC)**: Defined by IEEE 802.2. Communicates between network software in the upper layers and hardware in the lower layers. Places protocol identification tags in the frame header to indicate which Layer 3 protocol (IPv4, IPv6) is carried inside.
2. **Media Access Control (MAC)**: Implemented in hardware (IEEE 802.3 Ethernet, IEEE 802.11 Wi-Fi, IEEE 802.15 WPAN). Controls the physical NIC and handles:
   - **Data Encapsulation**:
     - Frame delimiting (preamble and start-of-frame flags for synchronization).
     - Physical addressing (source and destination MAC addresses).
     - Error detection (CRC/FCS in trailer).
   - **Media Access Control**: Regulates access to shared media and handles contention.

## Accessing the Medium
At each hop along a path across an internetwork, routers perform the following steps:
1. Accept the incoming frame from the physical medium.
2. De-encapsulate the frame, stripping the Layer 2 header and trailer.
3. Examine the destination IP address in the Layer 3 packet header to determine the best outgoing path.
4. Re-encapsulate the packet into a brand-new Layer 2 frame appropriate for the next segment's medium.
5. Transmit the new frame out the outgoing interface onto the physical medium.

# Network Topologies
The topology of a network defines the physical and logical arrangement of connected nodes:
- **Physical Topology**: Identifies actual physical connections, cable layouts, and hardware locations. Usually point-to-point (P2P) or star/extended-star.
- **Logical Topology**: Describes the virtual path and transmission mechanism frames follow to move between nodes, referencing IP addressing and interface configurations.

### WAN Topologies
#### Point-to-Point (P2P)
Consists of a direct, permanent link between two communicating endpoints.
![[Pasted image 20260203153512.png]]

#### Hub-and-Spoke
The WAN equivalent of a star topology: a centralized hub site interconnects multiple branch spoke sites via point-to-point circuits. Spokes cannot exchange traffic directly without traversing the central hub.
![[Pasted image 20260203153629.png]]

#### Mesh
Provides high availability by interconnecting all nodes directly to one another. Full mesh is costly and complex; organizations frequently employ **partial mesh** where only critical core sites have redundant interconnects.
![[Pasted image 20260203153747.png]]

### Point-to-Point WAN Characteristics
Frames placed on one end of a P2P link can only emerge at the opposite end.
**No MAC addresses are required in Point-to-Point WAN protocols (like PPP or HDLC)** because there are no competing hosts on the shared link.

### LAN Topologies
Modern LANs utilize **star** or **extended star** topologies centered around multi-port Ethernet switches.
Legacy LAN topologies:
- **Bus**: All nodes tapped into a single backbone coaxial cable terminated at both ends.
- **Ring**: Nodes linked in an unbroken closed loop; used by legacy Token Ring and FDDI.

## Half-Duplex vs Full-Duplex
- **Half-Duplex**: Both devices can transmit and receive, but only one direction at a time (e.g., WLANs, legacy Ethernet hubs).
- **Full-Duplex**: Both devices transmit and receive simultaneously without collision risk (modern Ethernet switches with point-to-point dedicated microsegments).

# Media Access Control Methods
1. **Contention-Based Access**:
   Nodes compete for access in half-duplex mode.
   - **[[resources/CSMA-CD|CSMA/CD]]**: Carrier Sense Multiple Access with Collision Detection (legacy bus / hub Ethernet).
   - **[[resources/CSMA-CA|CSMA/CA]]**: Carrier Sense Multiple Access with Collision Avoidance (IEEE 802.11 WLANs).
2. **Controlled Access (Deterministic)**:
   Nodes take turns in sequence (e.g. Token Ring token passing). Inefficient under modern traffic demands.
   ![[Pasted image 20260203170259.png]]

## Collision Mitigation: CSMA/CD vs CSMA/CA
- **CSMA/CD**: Devices listen before transmitting; if a simultaneous transmission produces a voltage collision, transmission halts, a jamming signal is sent, and a random exponential backoff countdown begins.
- **CSMA/CA**: In wireless environments where stations cannot detect simultaneous collisions while transmitting, stations declare transmission duration windows and wait for random backoff intervals before transmitting, requiring explicit ACK confirmations.

# Data Link Frame Structure
Every Layer 2 frame consists of three primary components:
1. **Header**: Contains addressing, frame delimiters, and type identifiers.
2. **Data / Payload**: Layer 3 packet.
3. **Trailer**: Frame Check Sequence (FCS / CRC) for error detection.

![[Pasted image 20260203190400.png]]

### Frame Fields
- **Frame Start / Stop Indicators**: Synchronization flags marking frame boundaries.
- **Addressing**: Source and destination MAC addresses on the local medium.
- **Type / Length**: Identifies the encapsulated Layer 3 protocol (e.g., `0x0800` for IPv4, `0x86DD` for IPv6).
- **Control**: Flow control and QoS priority markers.
- **Data**: Layer 3 packet [[resources/payload|payload]].
- **Error Detection (FCS)**: Cyclic Redundancy Check (CRC) calculated by the sender and verified by the receiver to detect bit corruption.

# Layer 2 Address Progression Across Routers
- **Host to Router**: Source MAC is PC; Destination MAC is Router Default Gateway.
  ![[Pasted image 20260203192906.png]]
- **Router to Router**: Router 1 de-encapsulates the frame, consults routing tables, and creates a new frame where Source MAC is R1's outgoing interface and Destination MAC is R2's interface.
  ![[Pasted image 20260203193101.png]]
- **Router to Destination Host**: Router 2 creates a new frame where Source MAC is R2's local interface and Destination MAC is the final target server's MAC address.
  ![[Pasted image 20260203193653.png]]

> **Lab Tip**: After de-encapsulating a received frame, the first thing a router does is examine the destination IP address and **determine the best path** using its routing table before re-encapsulating.

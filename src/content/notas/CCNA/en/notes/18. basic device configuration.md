# Switch Boot Sequence
1. **POST (Power-On Self-Test)**:
   - The switch executes a self-test program stored in ROM.
   - Verifies the CPU subsystem, DRAM, and the portion of the flash device that forms the flash file system.
2. **Boot Loader Execution**:
   - The switch loads the boot loader software into memory.
3. **Low-Level CPU Initialization**:
   - The boot loader initializes CPU registers, which control physical memory mapping, cache sizes, and memory bus speeds.
4. **Flash File System Initialization**:
   - The boot loader mounts and initializes the on-board flash file system.
5. **Locating and Loading the IOS**:
   - The boot loader locates and decompresses the Cisco IOS software image into RAM and transfers execution control to the IOS kernel.

### The `boot system` Command
If the `BOOT` environment variable is not explicitly set, the switch attempts to load and execute the first bootable executable image found in flash memory.
```text
S1(config)# boot system flash:/path/image-filename.bin
```

To verify the boot image path:
```text
S1# show boot
```

# Cisco Catalyst Switch Status LEDs
Cisco Catalyst switches feature multi-function LEDs to monitor health and port performance:

### RPS (Redundant Power System) LED:
- **Off**: RPS is disconnected or unpowered.
- **Solid Green**: RPS is connected and ready to supply backup power.
- **Blinking Green**: RPS is connected but providing power to another device.
- **Solid Amber**: RPS is in standby mode or an error condition exists.
- **Blinking Amber**: Internal switch power supply has failed; RPS is actively powering the switch.

### Port Status (STAT) LED (Default Mode):
- **Off**: No link, or port was administratively shut down.
- **Solid Green**: Valid Layer 1 link established.
- **Blinking Green**: Port is transmitting or receiving traffic.
- **Alternating Green/Amber**: Link fault detected.
- **Solid Amber**: Port is blocked by Spanning Tree Protocol (STP) to prevent switching loops (normal for ~30 seconds during listening/learning states).
- **Blinking Amber**: Port is actively blocked by STP to prevent a loop.

### Port Duplex (DUPLX) Mode:
- **Off**: Half-duplex.
- **Solid Green**: Full-duplex.

### Port Speed (SPEED) Mode:
- **Off**: Operating at 10 Mbps.
- **Solid Green**: Operating at 100 Mbps.
- **Blinking Green**: Operating at 1000 Mbps (1 Gbps).

### Power over Ethernet (PoE) Mode:
- **Off**: PoE mode not selected; no port faults.
- **Blinking Amber**: PoE mode not selected, but at least one port has experienced a PoE error or power denial.
- **Solid Green (in PoE mode)**:
  - *Port Off*: PoE is off.
  - *Port Green*: PoE is actively supplying power.
  - *Alternating Green/Amber*: PoE denied (device power request exceeds switch PoE power budget).
  - *Blinking Amber*: PoE turned off due to fault.
  - *Solid Amber*: PoE has been administratively disabled on the port.

# Recovering from a System Crash (Boot Loader Mode)
If the IOS becomes corrupted or missing, access the `switch:` boot loader prompt via console:
1. Connect a console cable to the switch console port and launch a terminal emulator (9600-8-N-1).
2. Unplug the switch power cord.
3. Reconnect power and, within 15 seconds, press and hold the **Mode** button while the System LED is green.
4. Release the **Mode** button when the System LED turns amber, then returns to solid green.
5. The `switch:` prompt appears in the terminal.

### Boot Loader Recovery Commands:
```text
switch: set
BOOT=flash:/c2960-lanbasek9-mz.122-55.SE7.bin

switch: flash_init
Initializing Flash...

switch: dir flash:
Directory of flash:/
  2  -rwx  11838464  c2960-lanbasek9-mz.122-55.SE7.bin

switch: BOOT=flash:c2960-lanbasek9-mz.122-55.SE7.bin
switch: boot
```

# Switch Management Access (SVI Configuration)
A Layer 2 switch requires an IP address and default gateway solely for remote in-band management (SSH, Telnet, SNMP, HTTPS).

> **Best Practice**: Never use the default management VLAN 1 for administrative access. Assign a dedicated management VLAN (e.g., VLAN 99).

```text
S1(config)# interface vlan 99
S1(config-if)# description Management-SVI
S1(config-if)# ip address 172.17.99.11 255.255.255.0
S1(config-if)# ipv6 address 2001:db8:acad:99::1/64
S1(config-if)# no shutdown
S1(config-if)# exit

S1(config)# ip default-gateway 172.17.99.1
```

*Note: The SVI remains down/down until the VLAN exists in the VLAN database and at least one active port is assigned to that VLAN.*

# Configuring Physical Switch Ports
### Manual Speed and Duplex
```text
S1(config)# interface FastEthernet 0/1
S1(config-if)# speed 100
S1(config-if)# duplex full
S1(config-if)# end
S1# copy running-config startup-config
```

### Auto-MDIX (Automatic Medium-Dependent Interface Crossover)
Auto-MDIX automatically detects cable types (straight-through vs. crossover) and configures internal pinouts.
```text
S1(config)# interface FastEthernet 0/1
S1(config-if)# speed auto
S1(config-if)# duplex auto
S1(config-if)# mdix auto
```
*(Note: Auto-MDIX requires that both speed and duplex are set to `auto`.)*

# Interface Error Analysis
```text
S1# show interfaces FastEthernet 0/1
```

### Input Errors:
- **Runts**: Frames smaller than 64 bytes; caused by collisions or malfunctioning NICs.
- **Giants**: Frames larger than the maximum allowed MTU size (> 1518 bytes untagged).
- **CRC Errors**: Cyclic Redundancy Check checksum mismatch; caused by electrical interference (EMI), faulty cabling, or loose connectors.
- **No Buffer**: Packets dropped because switch memory buffers are full.
- **Frame Errors**: Frames received with improper framing or CRC alignment.
- **Overrun / Ignored**: Input buffer exceeded hardware processing speed.

### Output Errors:
- **Collisions**: Standard in half-duplex; should **never** appear on full-duplex links.
- **Late Collisions**: Collisions that occur after 512 bits (64 bytes) of the frame have been transmitted.
  - *Primary Causes*: Excessive cable length exceeding IEEE Ethernet specifications, or duplex mismatches (one side full, other side half).

# Secure Remote Management (SSH Setup)
Telnet (TCP 23) transmits all commands and passwords in cleartext. SSH (TCP 22) enforces strong encryption. Verify cryptographic support with `show version` (the image name must contain `k9`).

### Step-by-Step SSH Configuration:
1. **Verify SSH support**:
   ```text
   S1# show ip ssh
   ```
2. **Configure an IP domain name**:
   ```text
   S1(config)# ip domain-name cisco.com
   ```
3. **Generate RSA cryptographic key pairs**:
   ```text
   S1(config)# crypto key generate rsa
   How many bits in the modulus [512]: 1024
   ```
4. **Create a local user with encrypted secret**:
   ```text
   S1(config)# username admin secret ccna
   ```
5. **Configure VTY lines**:
   ```text
   S1(config)# line vty 0 15
   S1(config-line)# login local
   S1(config-line)# transport input ssh
   S1(config-line)# exec-timeout 5 0
   S1(config-line)# exit
   ```
6. **Enforce SSH Version 2**:
   ```text
   S1(config)# ip ssh version 2
   ```

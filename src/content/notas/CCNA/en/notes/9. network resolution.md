# MAC & IP Addressing
### Destination on the Same Local Network
When a transmitting host must deliver a message, it initially knows only the Layer 3 destination IP address. To construct a Layer 2 Ethernet frame, the host must determine the physical destination MAC address of the target device.

Two primary addresses are assigned to any device on an Ethernet LAN:
- **Physical Address (MAC)**: Used for NIC-to-NIC delivery within the same local Ethernet segment.
- **Logical Address (IP)**: Used for end-to-end packet delivery from original source to final destination across internetworks.

### Destination on a Remote Network
When the destination IP (IPv4 or IPv6) resides on a remote subnet, the frame's destination MAC address is set to the **Default Gateway** interface MAC address (the local router).

# Address Resolution Protocol (ARP)
Under IPv4, **ARP (Address Resolution Protocol)** dynamically maps a known 32-bit IPv4 address to its corresponding 48-bit physical MAC address.

Every Ethernet frame contains:
- **Destination MAC**: Target host on the local segment (or default gateway if remote).
- **Source MAC**: Originating host NIC MAC.

## Core Functions of ARP
1. **Resolving IPv4 addresses to MAC addresses**.
2. **Maintaining an ARP cache / table** mapping IP addresses to MAC addresses in volatile RAM.

When a packet is dispatched to the Data Link layer for encapsulation:
- If the destination IPv4 address is on the local subnet, the host searches its ARP cache for that host's IP.
- If the destination IPv4 address is remote, the host searches its ARP cache for the default gateway's IP.
- If the entry exists, the frame is encapsulated immediately and sent.
- If no ARP entry exists, the host buffers the packet and generates an **ARP Request**.

### ARP Request and Reply Process
- **ARP Request**:
  - Sent as an Ethernet broadcast (`FF:FF:FF:FF:FF:FF`).
  - EtherType: `0x0806`.
  - Flooded by switches out all ports except the receiving ingress port.
  - Asks: *"Who has IP X.X.X.X? Tell IP Y.Y.Y.Y"*.
- **ARP Reply**:
  - Sent as a unicast frame directed specifically to the requester's MAC address.
  - Answers with the requested MAC address.
  - Requester updates its local ARP table and completes frame transmission.

If no response arrives before the ARP timeout expires, the pending IP packet is discarded because a Layer 2 frame cannot be formed.

---

## What Does IPv6 Use?
IPv6 does not use ARP. It uses the **[[resources/neighbor discovery|ICMPv6 Neighbor Discovery (NDP)]]** protocol:
- **Neighbor Solicitation (NS)**: Multicast query sent to the Solicited-Node Multicast address.
- **Neighbor Advertisement (NA)**: Unicast response providing the MAC address.

---

## ARP Cache Management
Entries in an ARP table are transient and age out after an OS-dependent period of inactivity (typically between 15 and 300 seconds on workstations, up to 4 hours on Cisco routers).

### ARP Inspection Commands
- **Cisco IOS**:
  ```text
  Router# show ip arp
  Router# clear ip arp
  ```
- **Windows / Linux**:
  ```cmd
  arp -a
  arp -d *
  ```

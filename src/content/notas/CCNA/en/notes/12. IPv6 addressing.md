## Why IPv6?
IPv6 was developed to replace IPv4 due to the impending depletion of 32-bit IPv4 address space.
Key characteristics:
- **128-bit address space**: Provides $2^{128}$ (approx. $3.4 \times 10^{38}$) unique addresses.
- Eliminates the need for NAT, restoring true end-to-end peer-to-peer reachability.

---

## IPv4 and IPv6 Coexistence Techniques
Because the migration to IPv6 is an ongoing global process, three primary coexistence mechanisms are used:
- **Dual Stack**: Allows devices to run both IPv4 and IPv6 protocol stacks simultaneously on the same physical link.
- **Tunneling**: Encapsulates an IPv6 packet inside an IPv4 packet to traverse IPv4-only networks.
- **NAT64 (Network Address Translation 64)**: Translates between IPv6-only devices and IPv4-only networks.

# IPv6 Address Representation
An IPv6 address consists of 128 bits divided into eight 16-bit blocks called **hextets**, separated by colons:
`2001:0db8:85a3:0000:0000:8a2e:0370:7334`

![[Pasted image 20260620193743.png]]

### Rules for Simplifying IPv6 Addresses
1. **Omit Leading Zeros**:
   - Any leading zeros in a 16-bit hextet can be dropped:
   - `2001:0db8:85a3:0000:0000:8a2e:0370:7334` $\to$ `2001:db8:85a3:0:0:8a2e:370:7334`
2. **Double Colon (`::`) Compression**:
   - A single contiguous string of one or more 16-bit hextets consisting of all zeros can be replaced with a double colon (`::`).
   - The double colon can only be used **once** per address.
   - If two equal runs of zero hextets exist, compress the leftmost sequence.
   - `2001:db8:85a3:0:0:8a2e:370:7334` $\to$ `2001:db8:85a3::8a2e:370:7334`
3. **Lowercase Hex Digits**: Standardized convention uses lowercase letters (`a` - `f`).
4. **Port Notation**: When specifying port numbers, enclose the IPv6 address in brackets: `[2001:db8::1]:80`.
5. **Subnet Prefix**: The `/64` prefix length is the industry standard for user LANs, perfectly matching the 64-bit Interface ID required by SLAAC.

# IPv6 Address Types
### 1. Unicast Addresses
- **Global Unicast Address (GUA)**:
  - Globally unique and routable on the public Internet (equivalent to public IPv4).
  - Prefix range: currently allocated from `2000::/3` (the `2001:db8::/32` block is reserved for documentation).
  - Structure:
    1. **Global Routing Prefix**: Assigned by the provider/RIR (typically `/48`).
    2. **Subnet ID**: 16-bit field used by an enterprise to identify internal subnets.
    3. **Interface ID**: 64-bit host identifier.

  ![[Pasted image 20260620195641.png]]

- **Link-Local Address (LLA)**:
  - Required on every IPv6-enabled interface.
  - Used for communications across the local link (e.g., neighbor discovery, default gateway routing).
  - Not routable beyond the local subnet.
  - Prefix range: **`fe80::/10`** (first 10 bits are `1111 1110 10`).
- **Loopback**: `::1/128` (equivalent to `127.0.0.1` in IPv4).
- **Unique Local Address (ULA)**: `fc00::/7` to `fdff::/7` (used for local internal communication, similar to RFC 1918 private IPv4).

# Cisco IOS IPv6 Configuration Commands
Enable IPv6 routing globally:
```text
Router(config)# ipv6 unicast-routing
```

### Static GUA and LLA Configuration:
```text
R1(config)# interface gigabitethernet 0/0/0  
R1(config-if)# ipv6 address 2001:db8:acad:1::1/64  
R1(config-if)# ipv6 address fe80::1:1 link-local  
R1(config-if)# no shutdown
R1(config-if)# exit  

R1(config)# interface gigabitethernet 0/0/1  
R1(config-if)# ipv6 address 2001:db8:acad:2::1/64  
R1(config-if)# ipv6 address fe80::1:2 link-local  
R1(config-if)# no shutdown
```

# Dynamic Addressing for IPv6 GUAs
IPv6 nodes use **ICMPv6 Router Solicitation (RS)** and **Router Advertisement (RA)** messages:
- **Router Solicitation (RS)**: Sent by a host to all-routers multicast (`ff02::2`) requesting addressing information.
- **Router Advertisement (RA)**: Sent by routers periodically (every 200 seconds) or in response to an RS to the all-nodes multicast (`ff02::1`).

### Three RA Allocation Methods:
1. **Method 1: SLAAC (Stateless Address Autoconfiguration)**:
   - *"I have everything you need: network prefix, prefix length, and default gateway."*
   - Host generates its own 64-bit Interface ID using EUI-64 or a randomized value.

   ![[Pasted image 20260624142102.png]]

2. **Method 2: SLAAC with Stateless DHCPv6**:
   - *"Here is your network prefix, prefix length, and default gateway. Query a stateless DHCPv6 server for additional parameters (e.g., DNS servers, domain name)."*
3. **Method 3: Stateful DHCPv6**:
   - *"I am your default gateway. Query a stateful DHCPv6 server for your GUA, DNS servers, and domain configuration."*

# Interface ID Generation: EUI-64 vs Random
### EUI-64 Process:
Derives the 64-bit Interface ID from the host's 48-bit MAC address:
1. Divide the 48-bit MAC into 24-bit OUI and 24-bit Device Identifier.
2. Insert the 16-bit hex value `FFFE` in the middle.
3. Invert the 7th bit (Universal/Local bit) of the OUI (0 becomes 1, 1 becomes 0).

![[Pasted image 20260624143628.png]]

### Randomized Generation:
Modern operating systems (Windows 10/11, macOS, modern Linux) generate a randomized 64-bit Interface ID for privacy reasons, preventing tracking across networks.

# IPv6 Multicast Addresses
Reserved prefix: **`ff00::/8`**.

### Well-Known Multicast Addresses:
- **`ff02::1`**: All-Nodes Multicast (all IPv6 devices on the local link; functions similarly to IPv4 broadcast).
- **`ff02::2`**: All-Routers Multicast (all IPv6 routers on the local link).

### Solicited-Node Multicast Address:
Special multicast address automatically mapped to a unique Ethernet multicast MAC address (`33:33:xx:xx:xx:xx`), enabling the host NIC to hardware-filter incoming traffic without passing non-relevant packets to the CPU.

# IPv6 Subnetting
Subnetting IPv6 uses the dedicated 16-bit **Subnet ID** field within the GUA:
- **16-bit Subnet ID**: Yields up to 65,536 subnets.
- **64-bit Interface ID**: Accommodates up to 18 quintillion hosts per subnet.
- Calculations are straightforward in hexadecimal without requiring binary conversions.

### Protocols and Standards
- A **protocol** is an agreed-upon set of rules defining how data is formatted and transmitted between devices across a network.
  - Proprietary protocols created for a specific manufacturer's hardware hindered multi-vendor interoperability.
- A **standard** is an open, consensus-driven specification describing how a protocol or technology should function.
  - Vendor-neutral standards ensure that any compliant hardware or software can communicate seamlessly.

#### Layer 1: Physical Layer
- Transmits and receives raw bitstreams as electrical voltages, optical pulses, or radio waves across physical transmission media.
- Specifies physical components: cables, pinouts, transceivers, signaling levels, and transmission bit rates.
- Examples:
  - UTP copper cabling
  - Fiber-optic cabling
  - Wi-Fi radio frequencies and antennas

#### Layer 2: Data Link / Network Access Layer
- Provides hop-to-hop frame delivery within a local network segment (switches do not count as hops; they merely extend the local broadcast domain).
- Employs Media Access Control (**MAC**) addresses to identify network interfaces on the local segment.
- Core protocols:
  - Ethernet (IEEE 802.3)
  - Wi-Fi (IEEE 802.11)

#### Layer 3: Internet Layer
- Provides end-to-end packet delivery between hosts across multiple interconnected networks.
- Uses logical **IP addresses** to identify hosts globally.
- Routers operate primarily at this layer, performing routing table lookups to forward packets toward the final destination host.
- Core protocols:
  - IPv4, IPv6
  - ICMP (Internet Control Message Protocol)

#### Layer 4: Transport Layer
- Provides process-to-process communication sessions between applications.
- Uses **port numbers** (0–65535) to identify specific application processes running on hosts.
- Operates primarily on communicating end hosts rather than network intermediate devices.
- Core protocols:
  - **TCP (Transmission Control Protocol)**: Reliable, connection-oriented, sequenced.
  - **UDP (User Datagram Protocol)**: Lightweight, connectionless, unacknowledged.

#### Layer 5: Application Layer
- Interface where network communication meets user applications and operating system processes.
- Defines message formatting, syntax, and semantics for exchanging application data.
- Core protocols:
  - HTTP / HTTPS
  - FTP, TFTP
  - SMTP, POP3, IMAP
  - DNS, DHCP
- Intermediate infrastructure devices (routers, switches) generally ignore application layer contents; they simply forward the underlying payload.

## Encapsulation and De-encapsulation

### Encapsulation
- The application layer generates and formats data to transmit across the network.
- As the data descends through the protocol stack, each layer prepends a protocol header containing control metadata:
  - Source and destination addresses (port numbers at L4, IP addresses at L3, MAC addresses at L2).
  - Layer 2 additionally appends a trailer containing a Frame Check Sequence (FCS/CRC) to detect transmission errors.
- The physical layer encodes the resulting frame into physical signals transmitted across the medium.

### De-encapsulation
- The receiving host senses signals on the physical medium at Layer 1 and reconstructs the bitstream.
- Layer 2 validates the frame checksum (FCS). If valid and addressed to the host (or broadcast/multicast), the Layer 2 header and trailer are stripped.
- The Layer 3 engine parses the IP header, verifies the destination address, and removes the L3 header.
- The Layer 4 engine inspects the destination port, handles sequencing/reassembly, strips the L4 header, and directs the data to the matching application process.
- The application processes the data and prepares an optional response.

### Protocol Data Units (PDUs)
At each stage of encapsulation and de-encapsulation, the data package carries a specific designation:
- **Segment**: Layer 4 PDU for TCP (or **Datagram** for UDP).
- **Packet**: Layer 3 PDU (IP header + L4 payload).
- **Frame**: Layer 2 PDU (Ethernet header + L3 payload + FCS trailer).

![[Pasted image 20260109182557.png]]

Formally referenced by layer number:
- **L4PDU**: Segment / Datagram
- **L3PDU**: Packet
- **L2PDU**: Frame

The underlying data payload contained within any given PDU is called the [[resources/payload|payload]] (excluding current-layer header and trailer).

### Adjacent-Layer and Same-Layer Interactions
- **Adjacent-layer interaction**: Each layer provides services to the layer immediately above it and consumes services from the layer directly beneath it.
- **Same-layer interaction**: Each layer communicates logically with its peer layer on the remote communicating host using standardized protocol headers.

##### The OSI Model
- Created by the International Organization for Standardization (ISO) as a 7-layer theoretical reference framework.
- Although proprietary OSI protocol implementations were ultimately eclipsed by the practical adoption of TCP/IP, the 7-layer terminology remains the universal industry standard for teaching and network troubleshooting.

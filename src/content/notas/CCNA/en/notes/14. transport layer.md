# Transport Layer Overview
The Transport Layer (Layer 4 in OSI and TCP/IP) manages end-to-end logical communications between applications running on different hosts. It acts as the liaison between the application layer and the underlying network transport.

### Core Responsibilities:
- **Tracking Individual Conversations**: Tracks multiple concurrent application sessions between source and destination endpoints.
- **Segmentation and Reassembly**: Divides application data streams into manageable chunks (segments or datagrams) and reconstructs them at the destination.
- **Adding Protocol Headers**: Attaches addressing (port numbers) and control information.
- **Application Identification**: Directs data streams to the correct application using port numbers.
- **Multiplexing**: Interleaves multiple data streams across a single network connection.

## Transmission Control Protocol (TCP) - RFC 793
TCP is a **connection-oriented**, highly reliable transport protocol providing guaranteed delivery and error recovery.

### Key Characteristics:
1. **Numbered Segments**: Assigns Sequence Numbers to track individual bytes transmitted.
2. **Acknowledgments (ACKs)**: Requires receiver acknowledgments; unacknowledged segments are retransmitted upon timer expiration.
3. **Ordered Delivery**: Reassembles out-of-order segments into the exact original sequence.
4. **Flow Control**: Regulates transmission rates based on receiver buffer capacity using dynamic window sizing.

- HTTP / HTTPS (Web browsing)
- FTP (File transfer)
- SMTP / POP3 / IMAP (Email)
- SSH / Telnet (Remote terminal access)

## User Datagram Protocol (UDP) - RFC 768
UDP is a **connectionless**, lightweight "best-effort" transport protocol without delivery guarantees or flow control.

### Key Characteristics:
- Low overhead (only 8 bytes of header).
- No session establishment or termination handshake.
- Lost datagrams are **not** retransmitted at Layer 4 (any retransmission must be handled by the application layer).
- Datagrams are delivered in whatever order they arrive.

- TFTP (trivial file transfer)
- VoIP and video streaming (real-time tolerance for dropped packets over latency)
- SNMP (network monitoring)

# Port Numbers and Socket Pairs
Port numbers identify source and destination applications within transport layer headers.

- **Socket Pair**: The unique combination of source IP + source port and destination IP + destination port:
  - E.g., `192.168.1.5:49152` $\to$ `192.168.1.7:80`

### Port Number Ranges (IANA):
![[Pasted image 20260703152059.png]]
- **Well-Known Ports (0 – 1023)**: Reserved for privileged network services (e.g., HTTP 80, HTTPS 443, SSH 22, DNS 53).
- **Registered Ports (1024 – 49151)**: Assigned to specific vendor applications upon request to IANA.
- **Dynamic / Private / Ephemeral Ports (49152 – 65535)**: Assigned dynamically by the client OS as the source port when initiating a connection.

# TCP Connection Lifecycle
### Three-Way Handshake (Connection Establishment)
1. **SYN**: Client sends a SYN segment with an Initial Sequence Number (ISN) to request a session.
   ![[Pasted image 20260703152710.png]]
2. **SYN-ACK**: Server acknowledges with an ACK and sends its own SYN segment with its own ISN.
   ![[Pasted image 20260703152955.png]]
3. **ACK**: Client acknowledges receipt of the server's SYN; session is now established.
   ![[Pasted image 20260703153032.png]]

### Four-Way Handshake (Session Termination)
1. Active closer sends **FIN**.
   ![[Pasted image 20260703153211.png]]
2. Receiver responds with **ACK**.
   ![[Pasted image 20260703153328.png]]
3. Receiver sends its own **FIN**.
   ![[Pasted image 20260703153400.png]]
4. Active closer responds with **ACK** and closes connection after a timeout.
   ![[Pasted image 20260703153426.png]]

### TCP Control Flags (6 Bits):
![[Pasted image 20260703153943.png]]
- **URG**: Urgent pointer field valid.
- **ACK**: Acknowledgment field valid.
- **PSH**: Push function (pass data directly to application).
- **RST**: Reset the connection abruptly due to error.
- **SYN**: Synchronize sequence numbers during connection establishment.
- **FIN**: Finish session (sender has no more data).

# TCP Flow Control & Congestion Management
- **Initial Sequence Number (ISN)**: Randomized at session startup to protect against sequence prediction attacks.
- **Selective Acknowledgment (SACK)**: Allows the receiving host to explicitly acknowledge non-contiguous segments, so only lost segments are retransmitted.
- **Window Size**: 16-bit field advertising the number of bytes the receiver can buffer before requiring an acknowledgment.

![[Pasted image 20260703162356.png]]

- **Maximum Segment Size (MSS)**: Typically 1460 bytes (Ethernet MTU 1500 bytes - 20-byte IP header - 20-byte TCP header).
- **Congestion Control**: Sender reduces its transmission rate upon detecting packet drops or delayed ACKs to prevent collapsing intermediate network switches and routers.

# Ethernet LAN Switching
Switches operate at Layer 2 (Data Link Layer).
Standard maximum Ethernet payload MTU is 1500 bytes.

Ethernet spans both the Physical Layer and the Data Link Layer:
- **LLC Sublayer (IEEE 802.2)**: Communicates with upper-layer protocol stacks (IPv4, IPv6) and network software.
- **MAC Sublayer (IEEE 802.3)**:
  - **Data Encapsulation**: Ethernet framing, physical MAC addressing, error checking with Frame Check Sequence (FCS trailer).
  - **Media Access**: Controls media placement. Operates in full-duplex by default (or [[resources/CSMA-CD|CSMA/CD]] in half-duplex legacy environments).

### Local Area Networks (LAN)
- Bounded and separated by routers, not switches.
- Confined to a localized physical perimeter (office suite, building, campus).
- Routers interconnect separate LAN broadcast domains.

## Ethernet Frame Structure (Layer 2)
The standard Ethernet frame size ranges between **64 bytes minimum** and **1518 bytes maximum**:
- 64 bytes total – 18 bytes (header + trailer) = **46 bytes minimum payload**.
- If payload is smaller than 46 bytes, padding bytes are appended.
- Frames exceeding 1500 bytes payload (up to ~9000 bytes) are **jumbo frames**.
- Frames smaller than 64 bytes are discarded as **runts**.

Preamble and SFD synchronize clocks and are not included in the 64-1518 byte count:
- **Preamble**: 7 bytes of alternating 1s and 0s (`10101010` x 7) for bit synchronization.
- **SFD (Start Frame Delimiter)**: 1 byte (`10101011`) marking the beginning of address fields.

***Header Fields:***
- **Destination MAC**: 6 bytes (48 bits).
- **Source MAC**: 6 bytes (48 bits).
- **Type / Length**: 2 bytes (16 bits):
  - Value $\ge 1536$ (`0x0600`): **EtherType** identifying the Layer 3 protocol (`0x0800` for IPv4, `0x86DD` for IPv6, `0x0806` for ARP).
  - Value $\le 1500$: Length field.

![[Pasted image 20260115182702.png]]

***Trailer Field:***
- **FCS (Frame Check Sequence)**: 4 bytes (32 bits) storing the Cyclic Redundancy Check (CRC) value calculated by the transmitting node.

## MAC Addresses
- 48-bit (6-byte) physical hardware address burned into the NIC ROM (**Burned-In Address / BIA**).
- Expressed as 12 hexadecimal digits (e.g., `00:1A:2B:3C:4D:5E` or `001a.2b3c.4d5e`).
- **First 3 bytes (24 bits)**: Organizationally Unique Identifier (OUI) assigned to the hardware manufacturer by the IEEE.
- **Last 3 bytes (24 bits)**: Vendor-assigned unique serial identifier.

![[Pasted image 20260216061703.png]]

#### Dynamically Learned Addresses
Learned automatically by switches from incoming traffic via source MAC examination. Cisco switches age out dynamic entries after 300 seconds (5 minutes) of inactivity.

#### Statically Configured Addresses
Manually assigned to an interface; they never age out and persist until removed.

---

Finding unknown MAC addresses:
- IPv4: [[resources/ARP|ARP (Address Resolution Protocol)]] using broadcast `FF:FF:FF:FF:FF:FF`.
- IPv6: [[resources/neighbor discovery|Neighbor Discovery (NDP)]] using ICMPv6 Solicited-Node multicast.
- Connectivity reachability testing: [[resources/ping|ping (ICMP)]].

### Types of MAC Traffic
1. **Unicast**: Targeted delivery to a single destination NIC MAC.
2. **Broadcast**: Processed by every host on the local broadcast domain:
   - MAC: `FF:FF:FF:FF:FF:FF`.
   - Switches flood broadcasts out all ports except the receiving ingress port.
   - Routers drop broadcasts; they do not forward them across subnets.
3. **Multicast**: Delivered to a specific subscribed group:
   - IPv4 Multicast MAC prefix: `01:00:5E:xx:xx:xx` (mapping IP range `224.0.0.0`–`239.255.255.255`).
   - IPv6 Multicast MAC prefix: `33:33:xx:xx:xx:xx` (mapping IP range `ff00::/8`).
   - Reserved protocol MACs (STP: `01:80:C2:00:00:00`, LLDP: `01:80:C2:00:00:0E`).

## MAC Address Table (CAM Table)
Switches populate and query the **Content Addressable Memory (CAM)** table to make forwarding decisions:
1. **Learning**: Examine the **Source MAC** of every incoming frame. If not present in the table, bind it to the ingress port. If already present, reset its 5-minute aging timer.
2. **Forwarding**:
   - If the **Destination MAC** is found and matches a different port $\to$ forward out that specific port (unicast).
   - If the Destination MAC is associated with the exact same ingress port $\to$ filter/discard the frame.
   - If the Destination MAC is unknown (or broadcast/multicast) $\to$ **unknown unicast flooding**: flood out all active ports except the ingress port.

Cisco IOS CLI commands:
- `show mac address-table`
- `clear mac address-table dynamic`
- `clear mac address-table dynamic address <mac-address>`

## Switch Forwarding Methods
1. **Store-and-Forward**:
   The switch buffers the entire frame, computes the CRC/FCS checksum, and drops corrupted frames. If valid, the destination MAC is looked up and forwarded. (Standard on Cisco Catalyst switches).
2. **Cut-Through**:
   Forwards the frame as soon as the 6-byte destination MAC address is read, without waiting for the remainder of the frame:
   - **Fast-Forward**: Lowest latency; forwards immediately after reading the destination address. Does not check for frame corruption.
   - **Fragment-Free**: Buffers the first 64 bytes (the minimum frame collision window) to filter out runts and collision fragments before forwarding.

## Memory Buffering in Switches
- **Port-Based Memory**: Separate fixed queue per port; susceptible to head-of-line blocking if an egress port becomes congested.
- **Shared Memory**: Dynamically allocates buffer space across all switch ports from a common memory pool. Ideal for switching between ports running at asymmetric speeds (e.g., 1000BASE-T to 100BASE-T).

## Duplex and Speed Autonegotiation
- **Autonegotiation**: IEEE 802.3u standard enabling two connected devices to exchange capabilities and automatically configure the highest common speed and duplex mode.
- **Duplex Mismatch**: Occurs when one port is hardcoded or misconfigured to half-duplex while the peer runs full-duplex, resulting in late collisions, CRC errors, and poor throughput.
- **[[resources/auto MDI-X|Auto MDI-X]]**: Automatically detects cable pinouts (straight-through vs crossover) and internally reverses Tx/Rx lines. Enabled by default on Cisco IOS 12.2(18)SE and later.

## Exam Questions & Highlights
- **Runt Frames**: Ethernet frames smaller than the 64-byte minimum size.
- **LLC vs MAC Sublayer**:
  - LLC is software-implemented (IEEE 802.2) and adds protocol tags identifying Layer 3 payloads.
  - MAC is hardware-implemented (IEEE 802.3) and performs media framing, addressing, synchronization, and error detection (FCS trailer).
- **Full-Duplex Media Access**: Does not require collision arbitration protocols because collision domains are eliminated.
- **Flooding Action**: Receiving frames with destination `FF:FF:FF:FF:FF:FF` or unknown unicast causes the switch to forward the frame out all ports except the ingress port.

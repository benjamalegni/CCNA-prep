# Small Network Topologies & Device Selection
In a small network, the number and variety of devices are significantly reduced compared to an enterprise campus, but the design must still ensure reliability and future growth.

### Device Selection Factors:
- **Cost**: Determined by port density, routing capabilities, switching performance, embedded hardware security, and redundancy.
- **Speed and Port Types**: GigabitEthernet vs. 10G uplinks, optical SFP transceivers, PoE capability for IP phones and access points.
- **Expandability**: Fixed vs. modular chassis configurations allowing future interface expansion.
- **Operating System Features and Services**:
  - Layer 3 switching
  - NAT (Network Address Translation)
  - DHCP services
  - Quality of Service (QoS)
  - Voice over IP (VoIP) support
  - Integrated security (ACLs, stateful inspection)

### Network Redundancy
- Eliminates single points of failure by duplicating critical links and hardware.
- Examples include dual homed connections to multiple ISPs and redundant switch uplinks.

### Traffic Management (QoS)
- Prioritizes latency-sensitive traffic (voice and video streams) over best-effort data traffic (web browsing, file transfers) during periods of congestion.

# Applications and Network Protocols
### Applications vs. Services
- **Applications**: Software interfaces interacting directly with the user (e.g., web browsers, email clients).
- **Network Services**: Background processes running on operating systems to format and transport application data (e.g., HTTP, SMB, DNS).

### Core Protocols:
- **Remote Management**: SSH (TCP 22)
- **Web**: HTTP (TCP 80), HTTPS (TCP 443)
- **Email**: SMTP (TCP 25), POP3 (TCP 110), IMAP (TCP 143)
- **File Transfer**: FTP (TCP 20/21), TFTP (UDP 69)
- **IP Addressing**: DHCP (UDP 67/68)
- **Name Resolution**: DNS (UDP/TCP 53)

# Scaling Small Networks
1. **Network Documentation**: Up-to-date physical and logical topology diagrams, device asset inventories, and addressing schemes.
2. **Protocol Analysis**: Utilizing protocol analyzers (such as **Wireshark**) to capture and decode network traffic, identify peak utilization trends, and detect anomalies.
3. **Network Baseline**: Recording latency, throughput, and error rates when the network is functioning normally. Baselines provide a performance benchmark during troubleshooting.

# Verification Commands
### Host Commands
- **Windows**:
  ```cmd
  ipconfig
  ipconfig /all
  ipconfig /release
  ipconfig /renew
  ipconfig /displaydns
  ```
- **Linux / macOS**:
  ```bash
  ip address
  ip route
  ifconfig
  ```
- **All Platforms**:
  ```cmd
  arp -a
  ```

### Cisco IOS Inspection Commands
- `show running-config`: Displays active running configuration.
- `show interfaces`: Checks interface operational status, line protocol, bandwidth, collisions, and errors.
- `show ip route`: Displays the active routing table.
- `show ip interface brief`: Summarizes IPv4 interface status and assigned IPs.
- `show ipv6 interface brief`: Summarizes IPv6 interface status and assigned IPs.
- `show cdp neighbors`: Shows directly connected Cisco devices using proprietary Cisco Discovery Protocol (CDP).
- `show cdp neighbors detail`: Displays neighboring device IP addresses, IOS version, capabilities, and platform models.
- `show lldp neighbors`: Standardized IEEE 802.1AB Link Layer Discovery Protocol equivalent to CDP.
- `terminal monitor`: Enables real-time logging output on remote VTY (Telnet/SSH) sessions.

# The 6-Step Troubleshooting Methodology
1. **Identify the problem**: Gather symptoms, question users, inspect device logs.
2. **Establish a theory of probable cause**: Formulate hypothesis from most likely to least likely.
3. **Test the theory to determine the cause**: Validate hypothesis or formulate a new one.
4. **Establish a plan of action and implement the solution**: Execute remediation with minimal service disruption.
5. **Verify full system functionality and implement preventive measures**: Confirm issue resolution and guard against recurrence.
6. **Document findings, actions, and outcomes**: Record solution for organizational knowledge bases.

# Common Network Failure Scenarios
- **Duplex Mismatch**: One endpoint set to Full Duplex while the other operates at Half Duplex. The link remains operational, but performance suffers severe packet drops, high latency, and late collisions.
- **IP Addressing Issues**:
  - DHCP exhaustion or server unreachable.
  - Windows hosts assign an APIPA address (`169.254.x.x/16`), allowing only local communication with other APIPA hosts but blocking gateway routing.
- **Default Gateway Misconfiguration**: Host can communicate with local subnet devices, but cannot access external networks or the Internet.
- **DNS Resolution Failures**: Host can ping external destinations by numeric IP address, but cannot resolve domain names.

# dispositivos
en una red pequena el numero y el tipo de dispositivos incluidos va a ser significativamente reducido comparado al de una red mas grande

## seleccion de dispositivos
- **costo**: de un switch o routers estan determinados por sus capacidades y features, como el numero y tipos de puertos, tecnologicas de seguridad embebidas, y teconologias avanzadas de switching.
	- otro elemento clave al determinar el costo es la cantidad de redudancia a incorporar en la red
- **velocidad y tipos de puertos/interfaces:** es una decision critica
- **expandibilidad**
- **features del sistema operativo y servicios:** deben tener sistemas operativos que puedan soportar los requerimientos de las organizaciones, como:
	- switching layer 3
	- NAT
	- DHCP
	- seguridad
	- QoS
	- VoIP
## redundancia
para evitar puntos unicos de falla, se deben duplicar equipos o enlaces criticos, por ejemplo, tener un segundo proveedor de internet de respaldo

### gestion del trafico
implementar QoS para dar prioridad al trafico en tiempo real.

# aplicaciones y protocolos
aplicaciones vs servicios:
- aplicaciones se comunican directamente con la red
- los servicios de capa de aplicacion operan en segundo plano para preparar la transferencia de datos (como smb, ftp)

la red depende de protocolos comunes como:
- SSH -> acceso remoto seguro
- HTTP/HTTPS -> web
- SMTP/POP/IMAP -> mail
- FTP -> archivos
- DHCP -> asignacion automatica de IPv4
- DNS -> resolucion de nombres de dominio

voz y video:
estas aplicaciones requieren una infrastructura de red solida y protocolos especificos como RTP/RTCP para minimizar latencia

# escalabilidad
- **documentacion de la red**: fisica y logica, como un inventario de dispositivos, un presupuesto y un analisis de trafico
- **analisis de protocolos**: protocol analyzer (analizador de protocolos) es una herramienta que **captura y analiza los paquetes que pasan por la red**, por ejemplo wireshark, para entender el trafico en horas picos, detectar problemas y optimizar el flujo de datos
- **monitoreo**: como el administrador de tareas en windows para ver como los empleados consumen recursos y ancho de banda

# verificacion de conectividad
- ping
- traceroute/tracert
- linea base: consiste en guardar registros (ping, traceroute) *cuando la red funciona bien para compararlos en el futuro y detectar si hay caidas o lentitud inusual*

# comandos host y cisco IOS
hosts:
- windows: ipconfig, ipconfig /all, ipconfig /release /renew, ipconfig /displaydns
- linux/macOs: ifconfig, ip address
- todos: arp -a
cisco IOS:
- show running-config (ver configuración actual).
- show interfaces (estado de puertos y errores).
- show ip route (ver la tabla de enrutamiento).
- show ip interface brief (resumen rápido del estado y la IP de cada puerto).
- show cdp neighbors (muestra información sobre dispositivos Cisco directamente conectados).
- show cdp neighbors detail (muestra mas info de cada vecino: IP, version de IOS, capacidades, plataforma).
	- CDP es propietario de Cisco; LLDP es el equivalente estandar (show lldp neighbors).
- terminal monitor (muestra los mensajes de logging/syslog en la sesion actual, util cuando se administra por SSH o Telnet y no por consola).
# troubleshooting
el proceso se compone de 6 pasos cientificos
1. identificacion del problema
2. establecer una teoria de las posibles causas
3. probar la teoria para determinar la causa exacta
4. establecer un plan de accion e implementar la solucion
5. verificar la solucion e implementar medidas preventivas
6. documentar los hallazgos, acciones y resultados

# escenarios de fallas comunes
- incompatibilidad de duplex: si un dispositivo esta en full duplex y el otro en half-duplex, **habra comunicacion pero con un rendimiento terriblemente lento**
- problemas de direccionamiento IP: errores manuales o falla de DHCP
	- si windows no encuentra DHCP, asigna una IP APIPA (**169.254.x.x**, rango link-local auto-asignado), dejandolo incomunicado con el resto de la red
	- ej: una IP como **169.254.10.3** es link-local/APIPA, se auto-asigna sola y no es utilizable para comunicarse fuera de ese enlace
- problemas de gateway: si el equipo no tiene configurada correctamente la IP de su router local, no puede acceder a internet u otras redes
- problemas de DNS: provoca que los usuarios no puedan entrar a paginas web usando un dominio, por ejemplo.
